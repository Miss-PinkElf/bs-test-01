# 毕设推进工作流

## 任务目标
以“桌宠毕业设计可交付版本”为主线，按阶段推进前端展示、简单对话、后端闭环、记忆能力与答辩材料，并在推进过程中持续留下可写论文、可答辩、可续接的记录。

## 范围边界
- 范围内：阶段拆分、任务状态、设计决策、实现过程记录、验证证据、答辩素材沉淀、阶段 handoff。
- 范围外：把所有细节都塞进单个 explore 目录；与当前阶段无关的深度研究型扩展。

## 成功标准
- 每个阶段都有明确目标、完成定义、关键文件和下一步。
- 每轮实现结束后，都能在 explore 状态文件中看出“做了什么、为什么这样做、还有什么没做”。
- 后续写毕业论文或准备答辩时，可以直接从记录中提取阶段划分、技术决策、问题修复过程和验证证据。

## 阶段规划
1. Phase A：前端桌宠展示与交互稳定
2. Phase B：前后端简单对话闭环
3. Phase C：基础记忆与配置能力
4. Phase D：轻量上下文感知
5. Phase E：答辩演示脚本与材料收口

## 当前阶段
Phase C：基础记忆与配置能力推进中，下一步切向 Phase D 的轻量上下文感知

## 记录原则
- 外层用本目录记录“毕设推进全局状态”。
- 内层具体功能继续按主题开 explore 子目录或使用 OpenSpec change workspace。
- 每完成一轮有产出的迭代，都要同步 `state.md`、`decision-log.md`、`learnings.md`。

## 退出条件
- MVP 范围内的前端展示、简单对话、基础记忆、演示脚本与必要文档全部完成。
- 可明确说明哪些内容已进入毕设交付，哪些内容仍属于后续产品演进。
