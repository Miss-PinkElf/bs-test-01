# 写论文用 README

## 这是什么

这个目录不是新的真相源，而是为了**写论文时查资料更快**单独整理出来的一组文档副本。

你写论文时，优先在这里找材料，不要再回 `zzz-docs` 全目录里到处翻。

## 先看什么

建议按下面顺序阅读：

1. `任务书.md`
2. `开题报告.md`
3. `需求清单-任务书与开题报告对齐.md`
4. `粮仓环境数据预测管理平台-PRD-滚动预测闭环版.md`
5. `数据库设计-滚动预测与高温预警版.md`
6. `后端接口与DTO-VO-Mapper设计-滚动预测版.md`
7. `数据库优先MVP-回归验证清单.md`

## 每个文件怎么用

### `任务书.md`

用途：

- 写“课题来源”“研究任务”“设计目标”
- 用来约束论文不要跑题

适合写进论文的章节：

- 绪论
- 课题背景
- 研究内容

### `开题报告.md`

用途：

- 写“研究背景”“国内外现状”“研究意义”“总体思路”
- 保持论文和开题口径一致

适合写进论文的章节：

- 绪论
- 研究背景与意义
- 研究思路

### `需求清单-任务书与开题报告对齐.md`

用途：

- 把任务书和开题报告里的要求统一成一份更容易落地的需求边界
- 防止论文写到一半时目标漂移

适合写进论文的章节：

- 需求分析
- 系统目标

### `粮仓环境数据预测管理平台-PRD-滚动预测闭环版.md`

用途：

- 写系统功能范围、主线业务、角色和页面模块
- 这是“需求分析”和“系统总体设计”之间的桥梁文档

适合写进论文的章节：

- 需求分析
- 功能设计
- 系统总体方案

说明：

- 这是**强烈建议保留**的文档，不是唯一必需，但非常适合当论文母稿
- 这个文件名里虽然还保留了“**滚动预测闭环版**”的历史命名，但你写论文时要按**当前实际口径**理解：
  - 当前系统主线是：**数据导入/管理 -> 汇总分析 -> 预测 -> 归档 -> 展示**
  - 当前系统**没有**把“**预测 -> 修正 -> 再预测**”做成正式业务入口
  - `prediction_task` / `prediction_result` 里和修正链相关的字段，目前只作为**扩展预留**
- 所以论文里如果提到这一点，建议写成：
  - 系统当前已实现预测任务、结果归档和预警展示
  - 修正预测链路保留了数据库扩展能力，但未作为本期核心交付功能实现

### `数据库设计-滚动预测与高温预警版.md`

用途：

- 写数据库设计章节
- 解释为什么要拆这些表、这些表之间是什么关系

适合写进论文的章节：

- 系统设计
- 数据库设计
- 数据表结构说明

### `后端接口与DTO-VO-Mapper设计-滚动预测版.md`

用途：

- 写系统实现章节
- 说明后端接口、模块分层和前后端联调关系

适合写进论文的章节：

- 系统实现
- 功能实现
- 接口设计

### `数据库优先MVP-回归验证清单.md`

用途：

- 写测试与验证章节
- 说明你验证了哪些链路

适合写进论文的章节：

- 系统测试
- 功能验证

## 哪些文档不要优先引用

下列文档已经不是论文主线真相源，写论文时不要优先引用：

- `zzz-docs/Archive/` 里的旧版 PRD、旧版数据库设计、旧版接口设计
- 迁移过程方案文档
- prompt 调试文档
- GSD 过程纪要

这些文档可以看，但只适合作为历史参考，不适合作为论文正文依据。

## 使用建议

1. 先用这里的文档写论文初稿，不要一开始就直接翻代码。
2. 写到“数据库设计”和“系统实现”时，再回头核对代码和 `schema.sql`。
3. 如果你后续又修改了源文档，记得把本目录里的副本同步更新。

## 一句话建议

写论文时，把这个目录当成你的“资料包”：

- `任务书/开题报告` 管方向
- `PRD` 管功能边界
- `数据库设计` 管结构
- `接口设计` 管实现
- `验证清单` 管测试与收尾
