## 1. 对齐结论

这次需求对齐的核心结论是：

- 任务书定义了“要交付什么”和“必须达到什么要求”。
- 开题报告定义了“系统具体做哪些功能”和“推荐采用什么技术路线”。
- 两份文档合起来，最终指向的是一个 **粮仓环境数据预测管理平台**。

它不是一个重硬件、重算法、重工业控制的大系统，而是一个以 **数据管理、图表展示、温度预测、平台化管理** 为核心的软件系统。

## 2. 系统最终可以做到什么

结合任务书和开题报告，系统最终应具备以下能力：

1. 管理粮仓基础信息
2. 管理用户与角色
3. 导入或录入粮仓历史温湿度数据
4. 对环境数据进行统一存储和分类管理
5. 按仓库、指标、时间范围查询历史数据
6. 以图表方式展示环境数据变化趋势
7. 对温度进行短期趋势预测
8. 展示预测结果并辅助管理人员判断风险
9. 归档预测结果和相关数据
10. 形成一个可运行、可演示、可提交代码与文档的完整系统

## 4. 技术栈对齐

## 4.1 任务书给出的技术范围

任务书给的是较宽的可选范围：

- 后端：Spring Boot / SSM
- 前端：Vue / React
- 数据库：MySQL / Oracle
- 可选工具：Python

这说明任务书强调的是“技术路线可行”，不是把技术栈完全定死。

## 4.2 开题报告给出的明确路线

开题报告给出的路线更具体：

- 后端：Spring Boot
- 持久层：MyBatis
- 数据库：MySQL
- 前端：Vue.js
- 图表：ECharts
- 预测：Java 实现简单线性回归或加权移动平均
- 架构：前后端分离

## 4.3 最终推荐采用的技术栈

如果目标是 **最贴合文档、最容易答辩、最稳妥实现**，建议采用：

- 后端：Spring Boot
- 持久层：MyBatis
- 数据库：MySQL
- 前端：Vue
- 可视化：ECharts
- 预测算法：线性回归 / 滑动平均 / 加权移动平均

如果只是做静态演示页，也可以暂时使用 React/Next，但这更适合作为页面预览方案，不是最贴合开题报告正文的正式技术路线。

## 5. 前后端分别需要做什么

## 5.1 前端需要做的内容

前端主要负责页面、交互和可视化展示，建议至少完成以下模块：

1. 登录页
2. 仪表盘首页
3. 仓库管理页
4. 环境数据录入页
5. 环境数据查询页
6. 历史趋势图页面
7. 温度预测结果页面

前端职责包括：

- 展示用户信息与角色信息
- 展示仓库信息列表
- 支持筛选查询
- 展示温度、湿度等图表
- 展示预测结果与风险提示
- 提供基本表单录入能力

## 5.2 后端需要做的内容

后端主要负责业务逻辑、接口和数据处理，建议至少完成以下内容：

1. 登录接口
2. 用户信息管理接口
3. 仓库管理接口
4. 环境数据录入接口
5. 环境数据查询接口
6. 预测接口
7. 预测结果存储接口或逻辑

后端职责包括：

- 设计数据库表结构
- 处理环境数据存储
- 实现数据查询
- 执行温度预测逻辑
- 返回前端可用的 JSON 数据
- 保证系统流程完整可联调

## 5.3 数据库需要做的内容

建议至少包含以下表：

- 用户表
- 角色表
- 用户角色关联表
- 仓库表
- 指标类型表
- 环境数据表
- 预测结果表

## 6. 哪些内容是必须做的，哪些不是

## 6.1 必须做

- 平台管理系统本身
- 环境数据管理
- 图表展示
- 温度预测
- 可运行系统
- 完整代码
- 文档与说明书

- 更复杂的预测算法
- 更丰富的异常预警
- Excel 导入
- 权限细化
- 更多环境指标

## 6.3 这次不建议做成主线

以下内容在开题报告中更多是背景或研究趋势，不建议作为本次主交付：

- 巡检机器人
- 数字孪生
- 区块链
- LoRa / 5G / GSM 通信层实现
- 深度学习大模型预测
