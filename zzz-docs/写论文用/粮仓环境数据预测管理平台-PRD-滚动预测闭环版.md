## 2. 产品定位

本课题定位为：

**一个以数据库设计、数据保存管理、预测结果归档、图表展示和预警输出为核心的粮仓环境数据预测管理平台。**

系统技术路线为：

- 后端：Spring Boot + MyBatis + MySQL
- 前端：Vue 3 + Element Plus + ECharts
- 运行形态：前后端分离 Web 管理平台

本期不追求复杂预测算法，而强调：

1. 数据能稳定入库
2. 数据能被查询、筛选、分页和管理
3. 预测任务与预测结果能归档追溯
4. 页面能清晰展示真实值、预测值与预警
5. 整体系统适合毕业设计答辩演示

## 3. 本期主线

当前主线已按 **Phase 1-9** 落地，包含以下内容：

1. 粮温固定模板 `XLSX` 下载与导入
2. 粮温原始测点数据入库与维护
3. 系统自动生成层温与整仓汇总分析
4. 湿度、二氧化碳等普通环境数据导入、录入、查询与趋势展示
5. 基于粮温汇总数据创建温度预测任务
6. 预测任务和预测结果写入数据库归档
7. 预测页展示实际值 / 预测值双线与任务摘要
8. 真实高温预警与预测高温预警展示
9. 管理端关键列表收口到服务端分页，去除运行时 mock 依赖
10. 公共展示大屏 `/screen` 使用真实接口聚合数据展示

## 4. 本期不作为主线的内容

以下内容继续视为扩展预留，而不是本期必做项：

- “预测 -> 修正 -> 再预测”完整业务入口
- 修正预测专用页面和 `/correct` 接口
- 独立 archive 归档表
- 复杂机器学习、深度学习、大模型训练
- 真实传感器联网接入、LoRa、5G、数字孪生、机器人

说明：

- `prediction_task` / `prediction_result` 中保留了修正链相关字段
- 这些字段用于扩展能力说明，不代表当前系统必须提供修正入口

## 5. 产品目标

### 5.1 总体目标

构建一个面向粮仓场景的环境数据预测管理平台，重点完成：

- 数据采集结果入库
- 数据管理与查询
- 粮温汇总与预警
- 预测任务执行与归档
- 图表展示与答辩演示

### 5.2 具体目标

1. 支持粮温固定模板导入，并保证模板结构与解析规则一致
2. 支持粮温原始测点记录长期保存、分页查询和手工维护
3. 支持系统自动生成 `grain_temp_summary`
4. 支持湿度、二氧化碳数据的导入、手工录入、分页查询和趋势图
5. 支持按仓库、时间、目标类型执行温度预测
6. 支持查看预测任务列表、详情、摘要、图表和风险等级
7. 支持删除无效或脏预测记录
8. 支持仪表盘和答辩展示大屏使用真实接口展示

## 6. 角色与使用方式

### 6.1 管理员

- 管理用户、仓库和全部数据
- 查看仪表盘、预警、预测归档和展示大屏
- 维护系统级数据与演示环境

### 6.2 仓库管理员

- 导入本仓粮温数据
- 维护本仓环境数据与粮温原始记录
- 发起预测任务
- 查看预测结果、图表和预警

### 6.3 查看者

- 只读查看仪表盘、图表、汇总结果和预测归档

## 7. 数据范围

### 7.1 粮温主线数据

粮温是本期主线，按三层结构组织：

1. `grain_temp_point`：测点定义
2. `grain_temp_record`：原始测点记录
3. `grain_temp_summary`：系统汇总分析结果

这样设计的目的：

- 体现数据库建模深度
- 保留原始数据可追溯性
- 让预测基于更稳定的汇总时序而非零散测点值

### 7.2 普通环境数据

湿度、二氧化碳等普通环境指标采用轻量单值时序结构：

- `sensor_metric`
- `sensor_data`

本期支持：

- 文件导入
- 手工录入
- 历史查询
- 趋势图展示

### 7.3 预测数据

预测数据与真实数据分离保存：

- `prediction_task`：预测任务主表
- `prediction_result`：预测结果明细表

本期重点在于：

- 保存预测上下文
- 保存预测结果
- 输出预测预警
- 支持历史任务回看、分页和删除

## 8. 核心业务流程

### 8.1 粮温导入流程

1. 用户下载固定模板 `XLSX`
2. 用户填写仓库、采集时间和测点矩阵
3. 系统解析模板并写入原始测点记录
4. 系统自动生成层均温、整仓均温和真实预警
5. 用户在数据页查看汇总趋势和分页结果

### 8.2 粮温数据维护流程

1. 用户按仓库、时间范围查看原始测点记录
2. 用户可按区域、层号、点位、温度区间、关键词筛选
3. 用户可新增、编辑、删除粮温原始记录
4. 系统联动重算同仓库同时间的汇总结果与真实预警

### 8.3 普通环境数据流程

1. 用户选择湿度或二氧化碳指标
2. 通过手工录入或模板导入写入系统
3. 系统保存到 `sensor_data`
4. 用户可查询列表与趋势图

### 8.4 预测流程

1. 用户选择仓库和预测目标
2. 用户可选训练时间范围
3. 用户选择预测天数并执行预测
4. 系统读取历史汇总数据
5. 系统生成预测任务与预测结果
6. 系统输出风险等级与预测预警
7. 页面展示任务摘要、双线图和预测记录表

### 8.5 展示与答辩流程

1. 仪表盘展示仓库总览、预警、健康度、最新粮温汇总
2. `/screen` 大屏展示上总览 / 中图表 / 下明细
3. 页面全部使用真实接口，不再依赖运行时 mock 数据

### 9.4 粮温数据模块

功能说明：

- 固定模板下载与导入

功能说明：

- 湿度、二氧化碳导入与录入
- 服务端分页查询
- 趋势图查询

### 9.6 预测模块

功能说明：

- 创建预测任务

### 9.8 仪表盘与展示大屏模块

功能说明：

- 仪表盘概览接口
- 近期预警、仓库健康度、最新粮温汇总分页模块
- `/screen` 公开展示大屏

## 11. 接口需求概览

当前论文与设计描述应至少覆盖以下接口分组：

1. 认证：`/api/auth/login`、`/api/auth/me`
2. 用户与角色：`/api/users`、`/api/users/page`、`/api/users/stats`、`/api/roles/options`
3. 仓库：`/api/warehouses`、`/api/warehouses/page`、`/api/warehouses/stats`、`/api/warehouses/options`
4. 粮温：`/api/grain-temp/import`、`/api/grain-temp/import/template`、`/api/grain-temp/records`、`/api/grain-temp/records/filter-options`、`/api/grain-temp/summaries`、`/api/grain-temp/summaries/page`
5. 普通环境数据：`/api/sensor-data`、`/api/sensor-data/trend`、`/api/sensor-data/import`
6. 预测：`/api/predictions`、`/api/predictions/tasks`、`/api/predictions/tasks/page`、`/api/predictions/tasks/{taskId}`、删除接口
7. 仪表盘与大屏：`/api/dashboard/overview`、`/api/dashboard/alerts`、`/api/dashboard/warehouse-health`、`/api/dashboard/grain-summaries`、`/api/dashboard/screen`

## 12. 验收标准

### 12.1 数据保存与管理

- 粮温模板可下载、可导入、可生成汇总
- 粮温原始记录可分页查询、筛选和维护
- 普通环境数据可导入、录入、查询和展示

### 12.2 预测与归档

- 可基于历史真实数据生成预测任务
- 预测任务与结果能写入数据库
- 能查看历史任务、切换任务并删除无效记录

### 12.3 图表与展示

- 预测页展示实际值与预测值双线图
- 仪表盘与 `/screen` 使用真实数据接口
- 真实预警与预测预警可在界面中体现

### 12.4 课题契合度

- 重点体现数据库设计、数据保存、数据管理和归档能力
- 预测作为平台功能之一存在，但不过度追求算法复杂度

## 13. 风险与应对

### 风险 3：页面说明与当前实现脱节

应对：

- 以真实页面和真实接口为主
- 对已删除的 mock 兜底逻辑不再继续保留产品描述

## 14. 最终结论

当前系统最核心的课题价值不是“修正链做得多复杂”，而是：

- 数据能不能稳定保存
- 数据能不能被查询、筛选和管理
- 预测结果能不能留痕和归档
- 图表能不能直观展示实际值、预测值和预警
- 页面能不能支撑毕业设计答辩展示

因此，本期正式交付应继续围绕：

**数据库优先、数据管理优先、预测归档优先、真实展示优先。**
