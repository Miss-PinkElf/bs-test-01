# 粮仓环境数据预测管理平台数据库设计定稿

## 1. 设计目标

本稿作为毕业设计正式开发阶段的数据库真相源，服务于以下目标：

- 支撑登录、用户管理、仓库管理、环境数据管理、多指标独立预测、预测归档的完整业务流程
- 严格贴合 `开发指导版 PRD`
- 只覆盖毕设 MVP 范围，不扩展硬件接入、机器人、数字孪生、区块链、复杂深度学习

## 2. 核心建模决策

### 2.1 环境数据按“单指标单行”存储

`sensor_data` 一行只保存一个仓库、一个时间点、一个指标值。

这样做的原因：

- 更适合后续按指标筛选和画趋势图
- 便于扩展温度、湿度之外的新指标
- 与前端查询条件和 ECharts 数据结构更一致

## 2.2 用户与角色分离，保留扩展空间

采用 `sys_user` + `sys_role` + `sys_user_role`。

虽然毕设演示通常一人一个角色，但保留关联表后：

- 当前可以简单使用
- 后续若要细化权限，不需要推翻表结构

## 2.3 仓库管理员与仓库归属直接挂在用户表

`sys_user.warehouse_id` 用于表示账号所属仓库。

这样可以直接满足：

- 管理员账号无归属仓库
- 仓库管理员只关联一个主要仓库
- 查看者账号可做平台级只读用户

## 2.4 预测归档采用“两层表”

本次定稿采用：

- `prediction_task`：记录一次预测请求
- `prediction_result`：记录该次预测产生的多个未来时间点结果

这样优于单表 `prediction_record`，因为它更容易支持：

- 预测历史列表
- 某次预测详情
- 预测参数、状态、摘要的单独展示
- 答辩演示中的“预测执行 -> 查看结果 -> 归档追溯”完整闭环

## 3. 表清单

| 表名 | 用途 | 说明 |
| --- | --- | --- |
| `warehouse` | 仓库基础档案 | 管理仓库编号、名称、位置、容量、负责人、状态 |
| `sys_role` | 角色定义 | 管理员、仓库管理员、查看者 |
| `sys_user` | 用户信息 | 登录账号、展示名、状态、所属仓库 |
| `sys_user_role` | 用户角色关联 | 支撑用户与角色映射 |
| `sensor_metric` | 指标定义 | 温度、湿度等指标的字典与阈值 |
| `sensor_data` | 环境数据 | 历史采样、手工录入、导入数据 |
| `prediction_task` | 预测任务主表 | 一次预测请求一条记录 |
| `prediction_result` | 预测结果明细 | 一次预测对应多个未来预测点 |

## 4. 关系说明

核心关系如下：

- 一个仓库对应多条环境数据
- 一个仓库对应多次预测任务
- 一次预测任务对应多条预测结果
- 一个用户可归属于一个仓库
- 一个用户可关联一个或多个角色
- 环境数据和预测任务通过 `metric_code` 关联指标字典

## 5. 各表说明

## 5.1 `warehouse`

用途：维护粮仓基础档案。

关键字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `warehouse_code` | `VARCHAR(64)` | 仓库编号，唯一 |
| `warehouse_name` | `VARCHAR(128)` | 仓库名称 |
| `location` | `VARCHAR(255)` | 仓库位置 |
| `capacity_ton` | `DECIMAL(10,2)` | 容量，单位吨 |
| `manager_name` | `VARCHAR(64)` | 负责人姓名 |
| `contact_phone` | `VARCHAR(32)` | 联系电话 |
| `status` | `VARCHAR(32)` | 仓库状态 |
| `grain_type` | `VARCHAR(64)` | 粮食品类 |
| `remark` | `VARCHAR(255)` | 备注 |

## 5.2 `sys_role`

用途：角色字典表。

建议初始角色：

- `ADMIN`
- `WAREHOUSE_MANAGER`
- `VIEWER`

## 5.3 `sys_user`

用途：系统用户账号。

关键字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `username` | `VARCHAR(64)` | 登录名，唯一 |
| `password` | `VARCHAR(128)` | 密码或密码摘要 |
| `display_name` | `VARCHAR(64)` | 页面展示名称 |
| `warehouse_id` | `BIGINT` | 所属仓库，可空 |
| `status` | `VARCHAR(32)` | 用户状态 |
| `last_login_at` | `DATETIME` | 最近登录时间 |

说明：

- 当前种子数据中密码为演示值，正式联调时应改为加密存储

## 5.4 `sys_user_role`

用途：用户与角色关联。

说明：

- 当前毕设前端可按“一人主角色”展示
- 数据库层保留多角色扩展能力

## 5.5 `sensor_metric`

用途：环境指标字典。

当前建议最少包含：

- `temperature`
- `humidity`
- `co2`

关键字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `metric_code` | `VARCHAR(64)` | 指标编码，唯一 |
| `metric_name` | `VARCHAR(64)` | 指标名称 |
| `unit` | `VARCHAR(32)` | 单位 |
| `min_threshold` | `DECIMAL(10,2)` | 最小阈值 |
| `max_threshold` | `DECIMAL(10,2)` | 最大阈值 |

## 5.6 `sensor_data`

用途：保存环境监测历史数据。

关键字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `warehouse_id` | `BIGINT` | 所属仓库 |
| `metric_code` | `VARCHAR(64)` | 指标编码 |
| `metric_value` | `DECIMAL(10,2)` | 指标值 |
| `collected_at` | `DATETIME` | 采集时间 |
| `source_type` | `VARCHAR(32)` | 数据来源，手工或导入 |
| `source_batch_no` | `VARCHAR(64)` | 导入批次号 |
| `quality_flag` | `VARCHAR(32)` | 数据质量标记 |
| `created_by` | `BIGINT` | 录入人 |

说明：

- 该表既支撑手工录入，也支撑后续 Excel/CSV 导入扩展
- `quality_flag` 已为“基础预处理”预留字段，但不额外引入复杂预处理表

## 5.7 `prediction_task`

用途：记录一次预测请求的主信息。

关键字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `task_no` | `VARCHAR(64)` | 预测任务编号，唯一 |
| `warehouse_id` | `BIGINT` | 预测所属仓库 |
| `metric_code` | `VARCHAR(64)` | 预测指标 |
| `algorithm_code` | `VARCHAR(64)` | 算法编码 |
| `algorithm_name` | `VARCHAR(64)` | 算法名称 |
| `future_steps` | `INT` | 未来预测步数 |
| `sample_size` | `INT` | 实际样本数 |
| `status` | `VARCHAR(32)` | 任务状态 |
| `risk_level` | `VARCHAR(32)` | 风险等级 |
| `requested_by` | `BIGINT` | 发起人 |
| `requested_at` | `DATETIME` | 发起时间 |
| `completed_at` | `DATETIME` | 完成时间 |
| `summary` | `VARCHAR(255)` | 摘要或失败原因 |

## 5.8 `prediction_result`

用途：记录一次预测任务的多条结果明细。

关键字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `task_id` | `BIGINT` | 关联 `prediction_task.id` |
| `step_index` | `INT` | 未来步序号 |
| `predicted_time` | `DATETIME` | 预测时间点 |
| `actual_value` | `DECIMAL(10,2)` | 后续可回填真实值 |
| `predicted_value` | `DECIMAL(10,2)` | 预测值 |

说明：

- 页面可用它绘制未来趋势线
- 也可以支持“预测值 vs 后续真实值”对比扩展

## 6. 索引与约束原则

本次定稿遵循以下原则：

- 编码类字段尽量唯一，如 `warehouse_code`、`role_code`、`metric_code`、`task_no`
- 高频查询路径建立组合索引，如环境数据按“仓库 + 指标 + 时间”查询
- 主业务关联尽量落外键，避免演示项目出现脏数据

当前核心索引：

- `idx_sensor_query (warehouse_id, metric_code, collected_at)`
- `idx_prediction_task_query (warehouse_id, metric_code, requested_at)`
- `uk_prediction_result_step (task_id, step_index)`

## 7. 初始化数据建议

`schema.sql` 当前已包含以下种子数据：

- 3 个默认仓库
- 3 个默认角色
- 3 个默认演示账号
- 3 个默认指标

作用：

- 便于后续做接口联调
- 便于前端快速看到管理页面和图表页面的基础对象

## 8. 与后端接口的直接映射

该数据库设计直接支撑以下主链路：

- 登录：`sys_user` + `sys_user_role` + `sys_role`
- 用户管理：`sys_user` + `sys_user_role`
- 仓库管理：`warehouse`
- 环境数据录入/查询/图表：`sensor_data` + `sensor_metric`
- 多指标独立预测：读取 `sensor_data`，按所选 `metric_code` 写入 `prediction_task` + `prediction_result`

## 9. 当前结论

这份定稿数据库设计已经能稳定支撑毕业设计 MVP：

- 业务流程完整
- 表结构足够简单
- 同时保留了少量后续扩展空间

后续正式开发默认以本稿和 `backend/src/main/resources/db/schema.sql` 为准推进接口、DTO/VO、Mapper 与 Vue 前端联调。
