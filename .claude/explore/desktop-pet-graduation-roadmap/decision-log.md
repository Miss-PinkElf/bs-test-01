# 决策日志

## 2026-03-24 决策：将 explore 记录升级为“毕设推进工作流”
- **背景**：原先的 `.claude/explore/desktop-pet-ui-debug` 更适合记录一轮前端调试，不适合长期承载整份毕业设计的阶段推进。
- **选择**：新增 `.claude/explore/desktop-pet-graduation-roadmap` 作为全局记录工作区，原 `desktop-pet-ui-debug` 保留为前端专项调试归档。
- **原因**：毕业设计需要按阶段留痕，既要支持后续开发续接，也要支持写论文和准备答辩；单一 debug 目录无法承载这些目标。
- **放弃的方案**：直接把 `desktop-pet-ui-debug` 重命名成全局目录。
- **影响**：后续每轮主线推进先更新全局目录，再在需要时进入具体模块的 explore 或 OpenSpec workspace。

## 2026-03-24 决策：下一阶段主线切换为“简单对话 + 后端最小闭环”
- **背景**：前端展示、拖拽、缩放和联动交互已达到当前阶段目标，需要进入 MVP 更关键的可演示能力。
- **选择**：优先推进 OpenSpec 中的 `Task 5` 与 `Task 6`，先做最小对话闭环。
- **原因**：相比继续打磨前端细节，对话闭环更直接决定毕设是否具备“可运行、可演示、可解释”的价值。
- **放弃的方案**：继续延长前端细节优化，或直接跳到记忆系统。
- **影响**：后续 superspec 应围绕“前端对话入口 + Python 后端问答接口 + 前后端联调”展开。
