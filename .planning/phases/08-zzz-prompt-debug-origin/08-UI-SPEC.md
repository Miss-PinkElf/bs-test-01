## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | 不适用 |
| Component library | Element Plus |
| Icon library | Element Plus Icons（默认） |

## Spacing Scale

声明值仅使用 4 的倍数：

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 图例点、状态标签内微间距、紧凑文案补白 |
| sm | 8px | 表头内元素、状态行、按钮组最小间距 |
| md | 16px | 卡片内默认间距、表单项间距、图表标题区间距 |
| lg | 24px | 大屏一级区块内边距、总览区与图表区间隔 |
| xl | 32px | 页面主分区间距、顶部与主体的视觉分隔 |
| 2xl | 48px | 重要模块断层、主图与下方明细之间的节奏断点 |
| 3xl | 64px | 仅用于超宽屏下页面上下安全留白，不用于普通卡片 |

Exceptions: 
- 顶部指标卡最小可点击/可聚焦热区按 **44px** 处理，保证演示时鼠标点选与键盘焦点稳定。
- 图表容器高度可使用 **320 / 360 / 420px** 三档，不强制套入 spacing token，因为这是图表语义尺寸，不是纯留白 token。

Phase 8 落地约束：
- 顶部总览卡之间固定 `16px`。
- 中部图表区主次卡之间固定 `16px`；大区块之间固定 `24px`。
- 底部明细三块信息默认 `16px` 间距，禁止为了“铺满”压缩到 12px 以下。
- 大屏四周安全边距桌面端使用 `24px`，超宽屏可扩为 `32px`；不再沿用当前 `30px` 这种非 token 值。

来源：
- 现有项目常用 `8 / 12 / 16 / 24 / 28`，本合同统一收敛到 8 点体系；其中 `12 / 28 / 30` 视为历史值，不作为 Phase 8 新增合同。
- 参考文件：`frontend/src/styles.css`、`08-CONTEXT.md`。

## Typography

本阶段只声明 4 个字号、2 个字重：

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

补充约束：
- 页面主标题使用 `28px / 600`，对应“大屏标题”与核心模块标题，不再使用当前 `34px` 与 `40px` 这类偏演示化数字。
- 指标卡数值可在 `28px / 600` 基础上按屏宽放大到 `32px`，但实现上仍以 Display 角色统一，不新增第五档字号。
- 二级卡片标题、图表标题、分区标题统一使用 `20px / 600`。
- 表格正文、说明正文、错误说明、空状态正文统一使用 `16px / 400`。
- 标签、辅助说明、图例、时间范围提示、卡片副标题统一使用 `14px / 400`。
- 禁止在单页内混用超过 4 个字号；禁止出现为了“科技感”使用过密字距或全大写英文标题的做法。

来源：
- 默认字体来自 `frontend/src/styles.css`。
- 标题/正文层级结合 `08-CONTEXT.md` 的“后台面板增强版”“稳定优先”“答辩可读性”确定。

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#09211d` / `#f3efe6` 双色体系 | `/screen` 深色主背景继续保留；管理台浅色体系作为信息卡内容对照来源 |
| Secondary (30%) | `rgba(255,255,255,0.04)` + `rgba(255,255,255,0.10)` + `#123f37` | 大屏卡片、表头、弱分隔、顶部条、次级面板 |
| Accent (10%) | `#0b7a75` | 主图高亮线、当前选中状态、主操作按钮、关键指标强调 |
| Destructive | `#d97706` | 风险预警、警示徽标、异常提醒；Phase 8 无删除类破坏操作，不用于普通 CTA |

Accent reserved for:
- 粮温趋势主线
- 当前激活的时间范围/模块切换态
- 顶部“进入后台”等主操作按钮主色态
- 核心指标卡中唯一一个“本轮主讲指标”的数值高亮
- 图表 hover / selected 的主反馈

明确禁止：
- Accent 不得用于所有按钮、所有标签、所有表格边框。
- 预警/异常信息优先使用暖色风险色，不和主业务强调色混用。
- 不新增“霓虹蓝、荧光紫”类独立大屏配色，避免偏离“后台面板增强版”。

Phase 8 颜色合同：
- 背景继续走深色大屏底，但卡片、表格、说明块仍保持后台面板式半透明浅层容器。
- 预警趋势、最新预警、重点仓库风险态使用暖色分层：一般关注用浅暖色、明确预警用更高对比暖色。
- 预测趋势可使用辅色紫系或橙系，但只作为次主线，不得压过粮温趋势主线。

来源：
- 现有 token：`frontend/src/styles.css` 中 `--brand-deep`、`--brand-main`、`--accent-warm`、`--panel-bg`、`--panel-line`。
- 上游决策：`08-CONTEXT.md` D-03、D-07、D-15、D-16。

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | 查看后台数据 |
| Empty state heading | 暂无可展示的大屏数据 |
| Empty state body | 当前时间范围内没有可用的粮温、预警或预测数据。请切换时间范围、检查接口返回，或先到后台补录数据后再查看大屏。 |
| Error state | 大屏数据加载失败，请先检查网络与接口状态；若仍无法恢复，使用“查看后台数据”进入管理台排查。 |
| Destructive confirmation | 不适用：Phase 8 仅查看与跳转，不设计删除、停用、覆盖类破坏操作。 |

分区文案合同：
- 页面总标题：`粮仓环境数据预测管理平台`
- 页面副标题：`答辩展示大屏`
- 顶部总览区标题不额外重复“总览”二字，使用指标卡自身标签表达。
- 中部图表区推荐标题：
  - `粮温趋势`
  - `预警趋势`
  - `预测趋势`
  - `仓库对比`
- 底部明细区推荐标题：
  - `最新预警`
  - `最近预测任务`
  - `重点仓库`
  - `说明`

说明块文案约束：
- 只允许 2～3 条短句，每条不超过 32 个汉字优先。
- 说明块只回答“这页展示什么、数据来自哪里、为什么可信”，不得再占据主视觉位置。
- 避免“系统功能介绍式”长段落。

状态文案约束：
- 加载中：`正在加载大屏数据，请稍候…`
- 图表无数据：`暂无趋势数据`
- 明细表无数据：`暂无记录`
- 单个模块降级：`该模块暂时无法提供真实数据，已隐藏演示占位内容。`

来源：
- CTA 与页面标题来自当前 `BigScreenView.vue`。
- 其余为空状态/错误状态/降级文案，为结合 D-04、D-15、D-16 给出的默认合同。

## Interaction Contract

### 1. 页面骨架
- 页面固定为 **上总览 / 中图表 / 下明细** 三段，不得回退成“左说明右表格”的轻量页。
- 顶部总览区优先展示 4 个指标卡：在线粮仓、粮温汇总、重点预警、已归档预测。
- 中部图表区必须存在一个主图位，**粮温趋势** 为主图，视觉权重最高。
- 其余图表采用 2 宫格或主次布局均可，但必须保证“预警趋势、预测趋势、仓库对比”都有稳定信息位。
- 底部明细区保留表格/榜单形态，不强行全部图表化。

### 2. 首屏与稳定性
- `/screen` 为公开路由，页面进入后 **先渲染骨架，再分模块加载数据**，禁止所有接口完成前整页阻塞。
- 首屏若任一模块失败，不得白屏；至少保留标题、总览卡骨架、可见错误提示与回退入口。
- 图表初始化必须晚于容器尺寸稳定；如有必要，使用延迟挂载或可见后初始化，优先消除白屏/卡住。
- 若四类图表同时渲染会引发明显卡顿，优先级为：粮温趋势 > 仓库对比 > 预警趋势 > 预测趋势。低优先模块允许后置加载。

### 3. 数据真实化与降级
- `fetchOverview()` 提供的数据优先直出到总览卡、最新预警、重点仓库。
- 真实接口缺失时，允许单模块降级，但必须满足：
  1. 主模块不降级为全量 mock；
  2. 降级模块需显式提示，而不是伪装成真实数据；
  3. 不展示大段演示说明替代主图。
- 底部说明块永远是次要信息，不能替代真实数据模块。

### 4. 图表交互
- 图表 hover 仅提供基础 tooltip 与系列高亮，不增加复杂 3D、轮播、自动漫游效果。
- 不做自动播放轮播；答辩场景以人工讲解为主，避免失控动画干扰。
- 若有筛选，仅允许轻量筛选：时间范围、仓库、趋势目标；默认不增加复杂联动面板。
- 图表切换与筛选后，响应时间超过 300ms 时需出现明确加载态。
- ECharts 仅保留必要动画，首屏动画总时长建议 <= 600ms。

### 5. 明细区交互
- `最新预警` 默认按时间倒序展示，最多首屏显示 5～8 条。
- `最近预测任务` 展示任务号/仓库/预测时间/风险级别等最少必要字段，不展开复杂详情。
- `重点仓库` 优先展示健康分、风险等级、最新均温/预测值中的高价值字段。
- 明细区默认以“可快速扫读”为目标，单表单屏不超过 6 行优先；超过后使用局部滚动。

### 6. 跳转交互
- 顶部保留两个明确动作：`查看后台数据`、`返回登录`。
- CTA 优先级：`查看后台数据` 高于 `返回登录`，因为排查链路更贴近本页目标。
- 跳转按钮必须在任何降级状态下仍可用，作为稳定兜底出口。

### 7. 响应式合同
- `>= 1440px`：优先展示完整三段式，图表区可 2x2 或主次布局。
- `1100px ~ 1439px`：顶部指标卡可保持 4 列；中部图表允许 2 列；底部明细允许 2 列 + 1 行换行。
- `< 1100px`：指标卡改为单列或双列；图表区纵向堆叠；操作区按钮自动换行。
- 小屏不追求“大屏感”，优先保证信息不断裂、不溢出、不白屏。

## Component Inventory

| Area | Component / Pattern | Contract |
|------|---------------------|----------|
| 顶部操作区 | `el-button` + 标题文案 | 仅保留 2 个动作，不增加多余控制按钮 |
| 总览区 | 指标卡（自定义卡片 + Element Plus 容器） | 4 卡优先，数值 + 标签 + 一句注释 |
| 中部主图 | ECharts 折线图 | 粮温趋势为主图，必须最突出 |
| 中部辅图 1 | ECharts 折线/柱状图 | 预警趋势，强调时间变化 |
| 中部辅图 2 | ECharts 折线/面积图 | 预测趋势，强调风险演进 |
| 中部辅图 3 | ECharts 柱状/条形图 | 仓库对比，强调横向差异 |
| 下部明细 1 | `el-table` 或榜单卡 | 最新预警 |
| 下部明细 2 | `el-table` 或紧凑列表 | 最近预测任务 |
| 下部明细 3 | 榜单卡 / 分数卡 | 重点仓库 |
| 轻量说明块 | 紧凑文本卡片 | 只能作为次要补充 |

禁止项：
- 不新增轮播屏、全屏自动切换器、3D 地图、装饰性大环图。
- 不引入第二套大屏 UI 框架。
- 不把说明表继续放在首屏主视觉左侧。

## Data-to-UI Mapping

| UI 模块 | 数据来源 | 真实化要求 |
|--------|----------|------------|
| 在线粮仓 | `fetchOverview().warehouseCount` | 必须真实 |
| 粮温汇总 | `fetchOverview().grainSummaryCount` | 必须真实 |
| 重点预警 | `fetchOverview().realAlertCount + predictionAlertCount` | 必须真实 |
| 已归档预测 | `fetchOverview().archivedPredictionCount` | 必须真实 |
| 最新预警 | `fetchOverview().latestAlerts` | 必须真实；字段不足时允许轻量格式化 |
| 重点仓库 | `fetchOverview().warehouseHealthList` | 必须真实 |
| 粮温趋势 | 优先复用粮温汇总/趋势相关真实接口 | 必须优先真实，是主图 |
| 预警趋势 | 允许新增统计接口 | 尽量真实；如暂缺可后置 |
| 预测趋势 | 允许新增统计接口 | 尽量真实；可弱化但不可伪造重 mock |
| 仓库对比 | `warehouseHealthList` 或新增统计接口 | 优先真实 |
| 最近预测任务 | 预测任务真实接口 | 尽量真实 |
