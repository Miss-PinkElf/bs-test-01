<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 浏览器 session → `X-Demo-Username` 请求头 | 当前 demo 鉴权依赖前端 session，后端必须重新查库确认用户和角色，不能直接信任前端自报角色。 |
| `AccessControlService` → 控制器/Service | 后续所有角色和仓库权限判断都建立在这层返回的 `CurrentUserContext` 上，若这里不统一，后续会出现前后端权限漂移。 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | S | `X-Demo-Username` 头 | mitigate | 后端只把 header 当作“查当前用户的键”，真实角色和仓库仍从数据库读取，不信任前端自报权限。 |
| T-13-02 | R | 后台写操作审计 | mitigate | 后续所有写操作都改为使用 `CurrentUserContext.userId`，不再继续写死 `createdBy/requestedBy = 1L`。 |
| T-13-03 | E | 越权语义混淆 | mitigate | 引入 `ForbiddenException` 并在 `GlobalExceptionHandler` 映射为 `403`，不再把越权访问误报成 `400`。 |
</threat_model>
