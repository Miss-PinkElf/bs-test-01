<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source repo -> ignored portable cache/release dirs | 构建脚本会把本地 JRE/MySQL 和打包产物引入 release；若边界不严，二进制和缓存会误入 git。 |
| frontend dist -> backend portable jar | 若 dist 未被正确打进 jar 或 history fallback 缺失，portable 包会只有 API 没有可刷新的界面。 |
| portable env vars -> backend datasource | portable jar 依赖 runtime 脚本注入数据库地址和端口；若 profile 设计错误，会退回系统 MySQL 或错误端口。 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | T | `.gitignore` / release layout | mitigate | 在 `.gitignore` 中显式忽略 `.runtime-cache/windows/`、`release/windows-portable/` 和 staging 目录；构建脚本仅向这些目录写入产物。 |
| T-12-02 | D | `scripts/build-windows-portable.ps1` | mitigate | 构建前先校验 `java.exe`、`mysqld.exe`、`mysql.exe` 存在，缺失则立即失败，阻止半成品发布包进入分发流程。 |
| T-12-03 | T | `backend/pom.xml` portable 打包 | mitigate | 通过可验证的 portable 打包路径把 `frontend/dist` 放入 jar `static/`，并用 grep/build 命令检查 profile 生效。 |
| T-12-04 | S | `application-portable.yml` datasource | mitigate | portable profile 只接受 `127.0.0.1:3307` 这一组默认运行参数，并由 runtime 脚本显式注入 `PORTABLE_DB_*`，避免误连系统服务。 |
| T-12-05 | E | `SpaForwardController.java` | mitigate | 路由回退仅覆盖非 `/api/**` 的页面 GET 请求，不允许把 API、真实静态文件或错误页错误转发到 `index.html`。 |
</threat_model>
