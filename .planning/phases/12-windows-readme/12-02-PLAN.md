<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| portable scripts -> bundled MySQL binaries | 错误的初始化、启动或停止逻辑会破坏 `data/mysql/` 或连接到系统 MySQL。 |
| portable scripts -> bundled Java backend | 主启动脚本需要把 portable profile、端口和数据库地址准确注入 jar；否则可能指向错误数据源。 |
| reset wrapper -> Phase 11 schema/baseline verifier | 若 portable reset 分叉到另一套 SQL 或不再跑 verifier，就会破坏演示库的一致性。 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-06 | T | `scripts/portable/start-portable.ps1` | mitigate | 首次初始化只发生在 `data/mysql/` 为空时；后续启动默认保留现有数据，不自动执行 reset。 |
| T-12-07 | D | `scripts/portable/start-portable.ps1` / MySQL | mitigate | 固定 MySQL 绑定到 `127.0.0.1:3307` 并等待端口就绪后再启动 backend，避免与系统 3306 冲突和启动竞态。 |
| T-12-08 | T | `scripts/portable/reset-portable-demo-db.ps1` | mitigate | reset wrapper 只能调用现有 `scripts/reset-demo-db.ps1` + `scripts/verify-demo-baseline.ps1`，禁止维护 portable-only SQL 副本。 |
| T-12-09 | R | PID/log management | mitigate | 使用 `run/*.pid` 和 `logs/*.log` 明确记录 portable 进程状态，停止脚本按 PID 优先、端口兜底，避免“脚本说已停但进程仍在”的不可追责状态。 |
| T-12-10 | E | mysql executable resolution | mitigate | `reset-demo-db.ps1` / `verify-demo-baseline.ps1` 增加显式 `-MySqlExecutable` 参数，让 portable wrapper 始终调用 bundled mysql，而不是 PATH 上的任意系统二进制。 |
</threat_model>
