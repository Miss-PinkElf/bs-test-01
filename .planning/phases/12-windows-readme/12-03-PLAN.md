## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| verifier script -> portable release processes | 验证脚本需要实际启动和停止 bundled MySQL/JRE；清理失败会遗留进程并污染验证结果。 |
| README -> users generating/distributing portable package | README 是开发者和答辩使用者的主要入口，若命令名、路径或分发边界不准确，会直接误导使用。 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-11 | R | `scripts/verify-windows-portable.ps1` | mitigate | verifier 采用“存在性检查 -> 启动 -> URL/API 检查 -> reset/baseline -> stop”固定顺序，并在 finally/cleanup 路径始终调用停止脚本。 |
| T-12-12 | D | portable verification cleanup | mitigate | 失败时也要执行 `stop-portable.ps1` 并返回非零退出码，避免后台进程残留导致后续验证结果失真。 |
| T-12-13 | S | README portable instructions | mitigate | README 只引用真实已实现的脚本名、目录名和端口，不引入未落地命令或“仓库自带大文件”的错误暗示。 |
| T-12-14 | I | verifier logging | mitigate | 验证日志只输出目录、URL 和通过项，不输出数据库口令、整段 SQL 或敏感配置内容。 |
</threat_model>
