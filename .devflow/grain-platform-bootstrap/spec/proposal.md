# Proposal

## 摘要

- 变更名称：粮仓环境数据预测管理平台 MVP 骨架
- 目标：基于开题报告输出可实施的数据库设计、接口设计、页面设计，以及前后端项目骨架和一键启动脚本。
- 为什么现在做：当前需求方向已足够明确，先完成 MVP 骨架可以降低后续毕业设计实现成本，并形成可演示基础。

## 范围

- 范围内：
  - 用户登录与角色区分
  - 仓库信息管理
  - 环境数据录入、查询与图表展示
  - 温度趋势预测
  - 仪表盘概览
  - 数据库设计、接口清单、页面清单
  - 前后端基础项目骨架
  - Windows 一键启动脚本
- 范围外：
  - 真实传感器接入
  - 机器人巡检
  - 数字孪生
  - 区块链
  - 复杂深度学习
  - 生产环境部署

## 用户场景

- 主流程：
  - 管理员登录系统，查看粮仓概览。
  - 维护仓库信息与用户信息。
  - 仓库管理员录入或导入环境数据。
  - 用户按仓库、指标、时间范围查询历史数据。
  - 用户查看温湿度趋势图与温度预测结果。
- 重要边界场景：
  - 没有历史数据时显示空状态，不报错。
  - 查询时间范围为空时，提供默认最近 24 小时数据。
  - 预测样本不足时，返回“样本不足”的友好提示。
- 失败态或空状态：
  - 登录失败提示账号或密码错误。
  - 仓库不存在时接口返回 404 风格业务错误。
  - 环境检查失败时脚本输出缺失依赖说明。

## 约束

- 技术约束：
  - 后端使用 Spring Boot。
  - 数据库使用 MySQL。
  - 持久层按 MyBatis 方向设计。
  - 前端使用 Vue + ECharts。
  - 预测算法保持轻量、可解释。
- 产品或设计约束：
  - 面向毕业设计演示，优先完整流程和可运行性。
  - 页面不要过度复杂，重点突出数据展示与预测结果。

## 风险与开放问题

- 风险 1：当前本机未检测到 Maven，脚本的“真正一键运行”受环境制约。
- 风险 2：若后续改为真实物联网接入，当前数据库与接口需要扩展设备维度。
- 开放问题 1：后续是否需要 Excel 批量导入。
- 开放问题 2：后续是否需要 JWT 或仅保留演示级登录。
