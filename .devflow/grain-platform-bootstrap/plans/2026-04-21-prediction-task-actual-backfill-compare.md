# 预测任务详情：回填后续真实值做对照

## 背景（Mini Align）

- **目标**：当用户在预测页查看一条历史预测任务时，图表中的“实际值”不再只停留在该任务执行当时的训练区间，而是继续回填该任务预测区间内后来录入的真实值，用于和原预测结果做对照。
- **范围**：仅调整预测任务详情的取数与组装逻辑，以及预测页图表对这一结果的消费方式；不改预测算法、不改任务创建流程、不改 `prediction_task` / `prediction_result` 表结构。
- **已确认口径**：
  - 当前“旧任务图只显示执行当时快照”不满足用户预期。
  - 目标口径改为“旧预测任务 + 预测区间内后续真实值回填对照”。
  - 历史任务列表中的任务摘要、执行时间、预测区间仍保持任务归档语义，不改为“实时任务”。

## 问题记录（现象 / 原因 / 解决）

| 项 | 内容 |
| --- | --- |
| **现象** | 例如 2026-04-25 执行的预测任务，在后来录入了 2026-04-27 的真实温度后，预测页图表仍只显示到 2026-04-25 的实际值，看不到预测后的真实回填。 |
| **原因** | 当前 `PredictionService.toTaskResponse -> loadActualSeries(PredictionTask task)` 严格按任务的 `trainStartTime` / `trainEndTime` 查询真实值，导致历史任务详情只回放“任务执行当时的训练快照”。 |
| **解决** | 对“任务详情展示”与“训练时使用的历史样本”分离：任务训练边界仍保留原值，但详情 `resultList` 组装时，额外补查 `forecastStartTime ~ forecastEndTime` 内已经存在的真实值，并按统一时间轴与 `prediction_result` 做并置展示。 |

## 轻量方案

### 1. 后端任务详情口径调整

- `PredictionService` 中保留当前 `predict(...)` 的训练样本逻辑，不改预测算法输入。
- 新增“任务详情展示专用”的真实值查询逻辑：
  - 训练区间实际值：继续使用 `trainStartTime ~ trainEndTime`
  - 回填区间实际值：新增查询 `forecastStartTime ~ forecastEndTime` 内已经录入的真实值
- `toTaskResponse(task)` 最终返回的 `resultList` 改为：
  - 训练区间真实值
  - 预测区间真实值（若已录入）
  - 预测结果值

### 2. 时间轴对齐规则

- 同一时刻若已有真实值和预测值，应落在同一个 `resultTime` 上，便于前端折线对照。
- 若预测区间某天尚无真实值，则该天 `actualValue = null`，`predictedValue` 保持原值。
- 不采用前端插值或“自动补一天一格”的视觉伪造方案，避免展示结果脱离数据库真实记录。

### 3. 前端消费边界

- `PredictionView.vue` 尽量复用现有 `resultList` 渲染，不重做图表组件。
- 若后端把同一天的真实值 / 预测值合并到统一时间轴，前端原则上无需改图表数据结构，只需要继续按 `actualValue` / `predictedValue` 双线渲染。
- 若实现中发现当前 `PredictionResultItemDto` 不足以稳定表达“同一时间同时有真实值和预测值”，再做最小 DTO 调整。
