# 正式前端过渡文案清理与数据大屏命名统一

## 背景（Mini Align）

- **目标**：清理正式前端 `frontend/` 中仍带有“骨架”“答辩”“演示入口”等过渡期语义的用户可见文案，让界面更贴近正式系统表达。
- **范围**：
  - `frontend/src/layout/ConsoleLayout.vue`
  - `frontend/src/views/LoginView.vue`
  - `frontend/src/views/BigScreenView.vue`
  - `frontend/src/router/index.js`
- **不做**：
  - 不改业务逻辑、接口、权限和布局结构
  - 不处理 `frontend-next/`、`README.md`、`zzz-docs/`、历史归档中的旧表述
  - 不顺手改与本轮无关的注释或论文口径

## 当前事实

| 项 | 当前情况 |
| --- | --- |
| 管理端布局 | 仍有 `正式版 Vue 管理端骨架`、`Vue 正式实现骨架`、`答辩演示入口` 等表述 |
| 登录页 | 仍有 `毕业设计正式开发入口` 与“先稳定下来”式过渡说明 |
| 大屏页 | 仍有 `答辩展示大屏` 与“仅保留答辩讲解所需的轻量说明” |
| 路由标题 | `/screen` 的公开页标题仍是 `展示大屏` |

## 方案选择

| 方案 | 描述 | 结论 |
| --- | --- | --- |
| A. 只改最显眼的 1-2 处标题 | 成本低，但会留下按钮、说明、副标题的旧口径 | 放弃 |
| B. 统一处理 `frontend/` 内当前用户可见文案 | 风险低、范围清晰、结果一致 | 采用 |
| C. 连带原型、README、论文文档一起清理 | 范围扩大，容易和当前前端交付混在一起 | 暂不做 |

## 最终选择

- 采用 **方案 B**：
  - 将 `/screen` 统一命名为 **数据大屏**
  - 将“骨架 / 答辩 / 演示入口 / 轻量说明 / 主视觉”类过渡表达改为正式产品文案
  - 保持现有页面结构与交互不变，只做文案收口
