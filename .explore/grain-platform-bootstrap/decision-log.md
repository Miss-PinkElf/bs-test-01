# 决策日志

## 历史决策摘要

> [#1] 2026-04-05 - 采用前后端分离的 Spring Boot + Vue Web 平台作为毕业设计落地方向，因为它最贴合开题报告且最适合答辩演示。
> [#2] 2026-04-05 - 将实现范围收敛为软件平台 MVP，不做真实硬件、机器人与数字孪生，因为这些不属于当前毕设最小交付。

## 完整记录

### [#3] 2026-04-05
- 决策：角色先采用管理员、仓库管理员、查看者三类。
- 原因：权限模型足够覆盖毕业设计常见演示场景，同时避免权限系统过度复杂。

### [#4] 2026-04-05
- 决策：预测算法先采用可解释的简单线性回归与移动平均思路。
- 原因：符合开题报告，不依赖额外机器学习框架，便于本科答辩解释。

### [#5] 2026-04-05
- 决策：一键脚本优先做“环境检查 + 启动”，而不是自动安装所有依赖。
- 原因：当前环境缺少 Maven，且网络受限，直接安装依赖的成功率不可控。

### [#6] 2026-04-06
- 决策：预测归档从单表改为 `prediction_task + prediction_result` 两层结构。
- 原因：更适合表达一次预测任务与多个未来预测点的关系，也更方便后续做预测历史列表、详情展示和归档追溯。

### [#7] 2026-04-06
- 决策：正式版 Vue 前端先引入 `Pinia + Element Plus + Axios`，并在 API 层做兼容适配，允许当前演示后端继续工作。
- 原因：这样可以先把正式技术路线和页面结构搭起来，同时避免因为后端仍是 demo DTO 而阻塞前端升级。

### [#8] 2026-04-07
- 决策：预测主线从“仅温度预测”调整为“独立多指标预测”，支持温度、湿度、二氧化碳浓度等指标按所选 `metricCode` 独立预测。
- 原因：任务书与开题报告明确环境数据是多指标管理，当前算法本质上是单序列趋势外推，通用化到多指标仍在毕设 MVP 范围内；但不扩展为多变量联合建模，避免范围失控。
